# Changelog

## 0.5.6

- Advance the admission compiler to `nano-git-history-capability-policy-v3` so
  explicit branch-switch plus lost-work recovery requests receive the required
  Git-history capability instead of encouraging wrapper bypasses.
- Replay the bounded exact original request (up to 4,096 bytes) in the existing
  same-context evidence-debt review so late acceptance criteria are not replaced
  by a 128-byte prefix.
- Classify explicit branch-switch plus lost-work language as requiring Git history,
  and reject direct Git executable alias creation when history access is denied.
- Add no provider call, checkpoint, fresh critic, task identifier, reward input,
  verifier input, or task-specific runtime route.

## 0.5.5

- Reset the scoring path to the 0.4.6 runtime lineage and add one bounded,
  task-neutral actor-native acceptance reminder to the initial contract prompt.
- Prefix ordinary tool results with typed command, timeout, truncation, and
  observed-effect evidence without adding a provider request or history item.
- Keep terminal transport settlement independent from the real command verdict;
  a settled nonzero exit remains transport-success with explicit failure evidence.
- Report bash effects as unobserved, read-only effects as not applicable, and
  direct file changed/unchanged status only from a bounded byte comparison.
- Block public export and scored execution until the changed exact contract bytes
  receive fresh owner approval and an immutable public-source binding.
